# 苏丹的游戏 — 阿尔图 Mod v0.3.0

这是可安装的开发原型，依据设计总稿v0.3及本轮补充制作，针对游戏v0.111.0。主角目前使用铁甲战士模型；圆桌三敌人暂用原版骑士团。卡面继续使用已有原创符号占位图。v0.3新增29张正常可获得牌，常规角色奖励池共59张（普通20、罕见28、稀有11），实现二阶思潮、贝姬代打及军队联动。未定稿的高阶路线与保留项见 verification/v0.3更新报告.md。

## 安装与使用

1. 将 package/ArtuMod 文件夹放入 Slay the Spire 2/mods，文件夹内需同时有 ArtuMod.dll、ArtuMod.pck、ArtuMod.json。
2. 保持 BaseLib v3.3.8 或兼容版本启用。当前工程以你本机安装的 BaseLib v3.3.8 DLL 编译。
3. 重启游戏，在模组列表启用阿尔图；新开一局选择「阿尔图」。
4. 队友也必须安装相同版本的阿尔图 Mod 及兼容 BaseLib。双客户端联机尚未实测，建议先进行单人测试。

也可在 PowerShell 运行 Install.ps1。它只复制本 Mod 的三个文件；已有版本会备份到本工程 backups 文件夹。卸载时，在游戏内禁用阿尔图 Mod；已有阿尔图角色存档需要本 Mod 才能继续。

## 已实现内容

- 初始十张牌：四种岩石苏丹牌各两张、调兵遣将、御用通行。起始生命暂用70，金币99。
- 16张苏丹牌，岩石/青铜/白银/黄金四个品级；逐张独立期限，禁止普通升级、普通移除与变化。
- 有效代价、御用通行免代价、色厉内茬双重代价、犬马声色重放、青铜奢靡使用与重放。消耗只影响本场战斗，不当作永久删除，也不替代成功使用。
- 为虎作伥：苏丹牌0费、使用后抽1张；有苏丹牌在手时禁止非苏丹牌与主动结束回合；支付失败逐次增加嘲弄后继续执行。不是按卡名共用计时器。
- 苏丹的嘲弄：生命硬上限动态为最大生命的(100－10X)%，向下取整；十层立即强制死亡，治疗/复活不能突破。苏丹之怒按你本次提供的0至10层阶梯。
- 黄金逾期：杀戮生命上限减半且不再增加；征服禁止获得力量/敏捷且敌人开局无实体；奢靡禁止未来金币收入；纵欲禁止治疗并将战斗中的治疗转给敌人。
- 四种并行军队；精兵3/6/9阈值；军队收益不吃只针对卡牌的罪证惩罚。
- 普通/罕见/稀有奖励牌、最新升级效果；读物和思潮不升级；思潮翻涌本身没有思潮标签。
- 低阶思潮的复制、三层成果、臣服转为虎作伥；可见思潮层数。
- 二阶触碰洁净、窥视黑暗、免于恐惧的自由；净悟、秘悟、觉醒独立计数，战斗收益不随层数叠加。触碰洁净首抽减费仅持续当前回合。二阶复制／进化与互斥规则已接入，高阶未完成凭证排除普通奖励。
- 苏丹牌保留诅咒身份，原版出牌事件／历史支持杀戮攻击与其他三系技能计数；复制不增加原牌使用事件或重置期限。青铜奢靡重放按次数相加。
- 为君分忧、王命之下、率兵冲锋、互通有无、特化部队等罕见牌及八张稀有牌。超级贝姬夫人严格按实时奇数位／偶数位两轮免费强制出牌，免苏丹代价，保留实际效果条件，随后结束回合；升级固有。
- 休息处换牌并继承剩余期限；欧洛巴斯牌盒升级；古老牙齿将御用通行替换为夹在书中的字条；达弗的 Dusty Tome 让阿尔图四选一黄金苏丹牌。
- 原版事件附加选项：垃圾堆、涌泉、沉没雕像、真理石板、审判、沉没宝库。
- 群龙无首：遗物换取、三张同名思潮形成成果、普通思潮奖励、双方确认的队友遗物交换。交换目前排除初始遗物、路线遗物以及有拾取效果的遗物，避免重复发放拾取奖励。
- 沉没宝库：按玩家及存档槽保存一个宝箱；覆盖、取走清空、无附魔限制、升级等级恢复。联机使用 BaseLib 自定义消息同步宝箱信息；这部分需要真实双客户端验证。
- 字条保留为革命路线身份证；议程检查、领取与「构思＋弑君计划」合成规则。
- 圆桌茶会「你们也配强迫我选择？」：移除一张青铜或以上杀戮苏丹牌后挑战王冠骑士、军阀、佣兵队长；多人逐人确认，任一人拒绝则不扣牌。胜利后每人获得两件随机遗物并回复20生命。行动表与验证范围见 verification/圆桌茶会.md。

## 验证

v0.1原型验证在 verification/runtime-final.json；v0.2圆桌验证在 verification/tea-mechanics.json、tea-live/result.json。v0.3机制报告在 verification/v03-mechanics.json，真实出牌场景在 verification/v03-live/result.json，编译记录在 verification/build-v03.log；完整变更与保留项在 verification/v0.3更新报告.md。

本机 DLL 编译无警告、无错误。验证在隔离游戏副本中运行，存档目录为 ArtuModVerification，不使用原游戏的存档目录。检查包括注册、文本、卡面资源、独立计时、序列化恢复，以及实际游戏命令中的代价、军队伤害、罪证、成长封锁、嘲弄生命上限、强制执行、十层死亡与禁止复活。它不等于图形界面通关或联机兼容性验收。无界面测试的屏幕震动和退出资源释放警告记录在日志中。

## 重新编译

安装 .NET 9 SDK 或更高版本后，运行：

```powershell
.\Build.ps1 -GameDir '<本机路径>' -BaseLibPath '<本机路径>'
```

项目直接引用已安装游戏和 BaseLib 的 DLL，不分发它们；没有用最新 NuGet BaseLib 覆盖你当前安装的版本。改代码时先编译，再复制 package 中的文件。卡面资源修改后可用 Python + Pillow 运行 tools/build_assets.py；不需要安装 Godot 编辑器即可重新生成本版纯贴图资源包。

## 开发方法与资料

技术栈是 C#/.NET、MegaDot/Godot、BaseLib 和 Harmony。关键开发能力是：

- 用 CustomCharacterModel、CustomCardModel、CustomPowerModel 和各内容池注册角色与卡牌。
- 用 CreatureCmd、CardCmd、CardPileCmd、PowerCmd、RelicCmd 修改游戏状态；选择使用 PlayerChoiceContext，避免联机时各自弹出本地选择却未同步。
- 用 SavedProperty 保存卡牌独立期限和遗物永久惩罚。可变列表/字典必须在 DeepCloneFields 中重新创建，防止不同玩家或同名实例共用数据。
- 只在现有钩子无法表达时用 Harmony；限制到阿尔图，不影响其他角色。
- 针对本机版本编译；游戏更新后重新检查 DLL 接口，再运行验证。
