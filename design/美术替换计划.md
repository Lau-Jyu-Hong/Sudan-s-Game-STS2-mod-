# 阿尔图 Mod 美术替换计划

基线：ArtuMod v0.4.8-alpha（`ae50f97`），游戏 v0.113.1，BaseLib 3.4.8。本计划只登记并排序现有美术缺口，不调整玩法，也不代表已制作美术。

- **P0**：先建立角色身份和开局视觉。交付一套阿尔图头像、选角画面和开局核心图标，再做苏丹牌版式。
- **P1**：完成角色在房间中的形象、专属事件、茶会遭遇及常用卡图。优先处理容易误认或需要反复辨认的对象。
- **P2**：补齐卡池、选择卡、低曝光界面和已分化的临时状态图标。优先级用于排期，未完成项不阻塞已验收的素材上线。

状态：**待制**＝几何占位或缺专属美术；**待替**＝借用原版视觉；**暂留**＝已有合法临时图，可继续使用。表中的类名、属性名和资源键用于定位接线，不是新增或更改游戏 ID 的建议。以下是包体与源码核验，不是新素材的游戏内目视验收。

| **D · 场景／特效接线** | 圆桌茶会专属战斗背景、出牌拖尾、选角转场、建筑师打击特效 | 可画茶会背景、转场静帧、光斑／纹理参考 | Godot 排背景层、遮挡、三怪站位和镜头；转场、拖尾、打击由动画／材质／粒子实现，并保留原触发时序。茶会静态背景可先完成，但不能算战斗模型或场景已验收。 |

### 首批验证与后续批次

1. **先做可审阅样图，不承诺整批出图。** 首批定为 8 张生成母图：阿尔图标准像、选角主画面、女术士的牌盒、四类苏丹牌主图、群龙无首。选角按钮与顶部头像由标准像派生；先用其中一类苏丹牌试制四级。提交母图、裁切图和实际显示尺寸对照，确认后再批量扩展。不提前购买工具或切换到计费 API。
2. **静态素材可先独立交付。** 样图通过后，先补 16 张苏丹牌、两张初始技能、遗物和三场专属事件；再按原优先级补常规牌。每批挑少量不同用途的卡先做手牌／奖励／百科预览，保留同一人物参考、色板、画幅、安全区和统一文件命名。旧包体是回退基线。
3. **动态路线单独设验证门槛。** 现有圆桌三怪委托原版 `VisualTemplate.GenerateAnimator`，不能只把原版场景路径改成一张 PNG。先用**一个**隔离原型验证待机、攻击、施法或受击、死亡、锚点与战斗结算，确认动画回调和同步行为不变，再接其余敌人及阿尔图的多场景形象。未通过就保留原动态模型，静态美术照常推进；不以动画视频或生成的散帧替代可控的游戏动作。
4. **输出与入包分开。** 母图、源图层／矢量稿和最终 PNG 分别保留；不把母图直接塞进运行包。先检查透明边、实际裁切、图名映射、体积和独立加载。现有 `build_assets.py` 是几何占位生成器，不能直接覆盖新图；后续接入应显式保留已定稿的资源和 `status/`。未验证的分辨率、动画工作流和工具安装状态不写成已实现。

工具依据：[Codex／ChatGPT 绘图说明](https://learn.chatgpt.com/docs/image-generation)、[Godot 2D 精灵动画](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html)、[Godot 2D 骨骼](https://docs.godotengine.org/en/stable/tutorials/2d/2d_skeletons.html)、[Spine 的 Godot 运行时说明](https://esotericsoftware.com/spine-godot)。这些是候选工作流；不代表本机已安装或已与当前游戏版本完成兼容测试。

## 6. 制作、接入与验收

1. 先出阿尔图头像、牌盒和一套苏丹牌样图；在游戏实用尺寸检查轮廓、深浅底、文字安全区与品级区分。确定样图后再批量铺开。
2. 事件以现有文案为依据。先验封面与选项文字遮挡，再验圆桌三怪的站位、受击、死亡、动画触发和战后返回。替换只能改变画面，不能改存档 ID、事件条件、房间逻辑、出牌顺序或随机数。
3. 卡面按奖励、手牌、牌库／百科、升级预览检查；同图项目逐项切到新资源后，检查没有误回退到书图。状态图检查 32 像素级小图、悬浮大图、层数可读性和敌我辨识。未做的原生界面、联机或旧存档回归单独标注。
4. 用独立测试游戏目录验证，重打包前备份并确保保留无关资源，尤其 `status/` 与已有贝姬资源。超级贝姬夫人的**卡图**待做；现有猫动画及猫叫不是缺失素材，也不要求因换卡图更换它们。
5. 素材入库时记录作者、来源、实际路径、许可与修改；第三方素材同步 `CREDITS.md` 及适用的署名文件。不要将原版游戏资产导出随 Mod 分发，不采用许可范围未明确的原作素材。发布前再核对安装包，更新记录保留末尾两项鸣谢。
